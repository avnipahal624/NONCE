# NONCE security limitations — 15 November 2026

This document is deliberately blunt. NONCE is a testnet prototype and a
sandbox, not an audited production custody system. Do not use it for real
assets.

## 1. Contract status

- `contracts/NONCEVault.sol` is **unaudited** by an independent party.
- It is **not deployed** from this repository and is not configured in the
  active Convex deployment.
- It is **ETH-only**. There is no ERC-20, NFT, upgrade, proxy, module, sweep or
  cross-chain path.
- There is no formal verification, bug bounty, insurance or legal review.
- The 53-test local suite, fuzz runs, invariant campaign and Slither pass are
  bounded engineering evidence, not a proof.
- The guardian set is fixed at three with a two-of-three threshold. Two
  colluding/compromised guardians can replace the owner after the recovery
  delay.
- A compromised owner can still spend within the rolling limit after the
  mandatory delay. The contract narrows blast radius; it cannot make a stolen
  signing device safe.
- A compromised monitor can freeze repeatedly (denial of service), but cannot
  withdraw, unfreeze, change policy, rotate guardians or approve recovery.
- There is no emergency sweep. Bad role configuration or lost keys can strand
  test funds.
- The 64-slot rolling reservation ring can fill; new requests then revert with
  `RollingWindowFull` until requests execute, cancel or expire.
- `cancelExpired` is permissionless but nothing in this repository operates a
  keeper for it.
- Policy changes do not retroactively cancel pending requests. If policy is
  tightened, operators must cancel affected requests or rely on freeze/recovery.
- A recipient contract that rejects ETH makes execution revert; there is no
  pull-payment fallback.

## 2. Sandbox limitations

- Sandbox balances, deposits, withdrawals, freeze state and guardian approvals
  are Convex records, not chain facts.
- Sandbox guardian approvals are **simulated**. No guardian key or account is
  created, and the signature mode is `SIMULATED`.
- Sandbox recovery changes the demo owner and epoch, not an on-chain owner.
- Demo policy delay is compressed to two minutes; the contract minimum is one
  day. Demo recovery delay is compressed; the contract minimum is two days.
- Demo USDC is a ledger entry with six decimals, not an ERC-20 token. The
  contract cannot hold or transfer it.
- Demo decoy signals are generated by an owner-authenticated in-app simulator.
  A sandbox owner can manufacture a signal. It is labelled `SIMULATED` and must
  never be presented as independent detection.
- There is no production monitor, mempool watcher, phishing detector, external
  alert channel or on-call service.
- Evidence hashes and audit rows are ordinary database records. A database
  operator could alter them; there is no external anchoring or write-once store.
- A stolen NONCE account can perform sandbox actions and read records, but it
  cannot sign a testnet transaction without the wallet.

## 3. Testnet console limitations

- The console observes **one globally configured contract**, not a per-user
  testnet vault. Any signed-in account sees the same public chain state.
- No contract address, deployment hash, RPC URL or verification flag is
  configured in this workspace, so the console must show blockers.
- Reads trust the configured RPC. The new chain-ID check rejects a mismatched
  chain, but a malicious RPC can still lie about state at the correct chain ID.
- The console verifies a transaction receipt through the RPC; it does not prove
  finality or survive an arbitrary deep reorg.
- The indexer is a bounded polling worker. It does not see failed transactions,
  mempool activity, off-chain phishing or signatures that never reached a log.
- The indexer holds no monitor key and does not automatically freeze. Freezing
  remains a human wallet action.
- There is no guardian approval app, hardware-wallet flow, transaction
  simulation, off-chain signature collection or EIP-712/ERC-1271 support.
- The console has no allowlist or guardian-rotation forms yet, even though the
  contract ABI supports them.
- Wallet connection does not persist across reload. Gas is estimated by the
  wallet; the app does not simulate the call before submission.
- The app supports Base Sepolia only. There is no mainnet path.

## 4. Decoy and incident limitations

- The only working signal source is the owner-triggered sandbox simulator.
- The live indexer classifies confirmed contract logs into alerts; it does not
  feed those alerts into the sandbox incident state machine.
- There is no authenticated external webhook or signed watcher heartbeat.
- The sandbox auto-response path creates a simulated lockdown request only when
  monitoring is `ACTIVE` and risk is `HIGH`. It does not sign a contract
  transaction and does not prove a real freeze.
- A second signal during an open incident is now attached to the incident with
  evidence, but the original incident risk is not automatically escalated.
- Low-risk unsolicited transfers are intentionally recorded as noise and never
  freeze a vault.
- The contract's monitor is freeze-only by design. An automated monitor with a
  real key would require isolated custody, rate limits, replay protection, a
  kill switch and independent review; it is not implemented.

## 5. Authentication and operations

- Convex Auth authenticates sessions; the demo resolves vaults by `userId`.
- The wallet challenge domain check depends on deployment configuration. If
  `NONCE_ALLOWED_DOMAINS`/`SITE_URL` is missing or misconfigured, phishing
  resistance is weaker.
- No NONCE account recovery exists beyond signing in again.
- No email/push/SMS delivery is configured; notifications are in-app only.
- Scheduler execution is best effort; stored timestamps remain authoritative.
- No backup/restore drill, load test, soak test or disaster recovery exercise
  was run.
- No cost model, SLA or production on-call rotation exists.

## 6. Verification limits

- Playwright tests are checked in but **no app assertion executed**: the run
  failed at browser launch because the host could not install Chromium due to
  disk space (`ENOSPC`).
- No MetaMask or other wallet E2E was possible.
- No real testnet deposit, withdrawal, guardian approval, freeze, recovery or
  restoration was executed.
- No Basescan source verification was performed.
- No accessibility audit, screen-reader test or physical-device matrix was run.
- The repository lint run passes with 19 warnings; they are style/export-shape
  warnings, not suppressed errors.
- Git metadata is unavailable to this host, so source hashes are used instead
  of a commit hash.

## 7. Before any testnet demonstration

1. Configure a deployed address, RPC, deployment hash and verification result.
2. Verify the on-chain owner, monitor, guardians, policy and immutable delays.
3. Run a small deposit and a withdrawal that cannot execute early.
4. Confirm a rejection from the wrong guardian/non-guardian.
5. Confirm a freeze receipt and read `frozen()` afterward.
6. Confirm recovery quorum, delay and epoch invalidation.
7. Run the Playwright suite on a host with a browser, including mobile project.
8. Record actual hashes, receipts and block numbers; never substitute dry-run
   addresses or simulated references.

## 8. Before any real-value use

Do not use this contract with real value. Before that could be considered:

1. independent audit and remediation review;
2. independent invariant/fuzz campaign with published seeds;
3. production key custody for owner, monitor and guardians;
4. a monitored deployment with alerting, on-call and a rehearsed freeze;
5. a separate guardian approval application with decoded transactions;
6. external evidence anchoring and retention;
7. legal, regulatory and insurance review;
8. a separate mainnet deployment plan. This repository does not authorize one.
